Much more free memory: about 76 KB more internal RAM on ESP32-S3 boards and about 50 KB more on the classic ESP32, with no limits lowered.

## What changed

- **ESP32-S3: tables and network buffers moved to PSRAM.** The learned-signal catalog, the automation rule table and the Wi-Fi/lwIP static buffers now live in PSRAM. On an N16R8, free internal RAM rises from about 33 KB to 109 KB, and the largest free block from about 20 KB to 63 KB (the dashboard flags anything under 32 KB as fragmented). PSRAM was already required on the S3 images, and still is.
- **All boards: compact signal storage.** Every learned signal and both signals of every automation rule used to reserve 516 bytes for raw pulses, even for decoded remotes, which need about 16. Decoded signals are now stored inline, and only raw signals keep a pulse buffer, allocated while they are loaded.
  - The rule table shrinks from 36.4 KB to 3.5 KB, and the learned-signal table from 17.9 KB to 1.5 KB.
  - On the classic ESP32, which has no PSRAM, free internal RAM rises by about 50 KB.
  - Each raw signal costs about 520 bytes while loaded, so a setup that is all raw signals uses about as much as before.
  - The limits (32 learned signals, 32 rules) and the stored data format are unchanged.
- **CI.**
  - Runs start only for changes that affect a build or test, and never overlap.
  - Release tags rebuild only the version-stamped images.
  - Build jobs use 8-core Namespace runners.

v1.4.0 installs over v1.0.x to v1.3.x by OTA, and existing signals, rules, history and settings are kept.

**Full changelog:** https://github.com/Niklaus1911/esp32-cc1101/compare/v1.3.0...v1.4.0

## Firmware downloads

Each board has its own image. Never install one profile's image on another board, and never use OTA to change profiles.

| Board profile | Chip | Flash / PSRAM | Download |
|---|---|---|---|
| `esp32-devkit` | ESP32 | 4 MB / none | `rfbridge-v1.4.0-esp32-devkit.zip` |
| `esp32s3-devkitc-n16r8` | ESP32-S3 | 16 MB / 8 MB Octal | `rfbridge-v1.4.0-esp32s3-devkitc-n16r8.zip` |
| `xiao-esp32s3` | ESP32-S3 | 8 MB / 8 MB Octal | `rfbridge-v1.4.0-xiao-esp32s3.zip` |
| `esp32s3-supermini-fh4r2` | ESP32-S3 | 4 MB / 2 MB Quad | `rfbridge-v1.4.0-esp32s3-supermini-fh4r2.zip` |

Each zip contains the application image, bootloader, partition table, initial OTA data, a `flash_args` file with offsets, checksums and license notices. The standalone `rfbridge-v1.4.0-<profile>.bin` assets are the same application images, provided for OTA. `SHA256SUMS` covers every asset.

### Update from an earlier release (OTA)

Use **Web UI > System > Firmware update** with `rfbridge-v1.4.0-<profile>.bin`, or from a source checkout:

```bash
tools/push-ota.sh <hostname>.local rfbridge-v1.4.0-<profile>.bin
```

The device must be on Wi-Fi in service mode `web` or `both`, and the image's profile must match the running board. OTA writes the image to flash as it arrives, so a weak Wi-Fi link can drop the upload. If that happens, the device keeps running its current firmware and you can retry from a better position.

### First install, or a board running other firmware (wired)

Extract the zip for your board, then from inside that folder:

```bash
# Optional but recommended if the board already holds learned signals or network settings:
esptool --chip <esp32|esp32s3> --port <serial-port> read-flash 0x9000 0x6000 nvs-backup.bin

esptool --chip <esp32|esp32s3> --port <serial-port> write-flash @flash_args
```

`flash_args` preserves NVS at `0x9000` (size `0x6000`). **Do not run `erase-flash`**, and do not merge these files into one image: padding the gap between the partition table and OTA data would wipe NVS.

## Safety

The Web UI, OTA endpoint and Wi-Fi setup are intentionally unauthenticated. Anyone on the LAN can control the radio, install firmware or move the device to another network. Only run it on a trusted network and never expose port 80 to the Internet. Use the CC1101 at 3.3 V only, always with an antenna, and follow your local RF regulations. Power generic receiver modules at 3.3 V and always connect their GND.
