Change the device's Wi-Fi network from the Web UI, with an automatic fallback so a mistake can't strand it.

## What changed

- **Join a Wi-Fi network from the Web UI.** **System > Wi-Fi > Join network** takes an SSID and password (empty for an open network) and asks for confirmation. Names and passwords with spaces and symbols work. The device answers before leaving its current network; if your browser can't reach the new network, open `http://<hostname>.local/` from that network. Changes are refused while an OTA upload runs.
- **Automatic fallback.** If a newly requested network fails five attempts without getting an address, the device returns to its saved network by itself and shows the failed name as **Last failed join** (`failed_ssid` in `/api/live`). This also protects the UART `wifi connect` command. A new network is saved only after it connects.
- **Password handling.** The password is sent once in the form body over the trusted-LAN HTTP connection, wiped from request buffers after use, and never returned by any endpoint. Like OTA, Wi-Fi changes are unauthenticated: anyone on the LAN can move the device to another network.
- **Console fix.** In generic RF mode, `status` dropped the CC1101 diagnostics row and logged `Could not format dashboard value`; the row now shows as `CC1101 diag`.

v1.2.0 installs over v1.0.x and v1.1.x by OTA, and existing signals, rules, history, and settings are kept.

**Full changelog:** https://github.com/Niklaus1911/esp32-cc1101/compare/v1.1.0...v1.2.0

## Firmware downloads

Each board has its own image. Never install one profile's image on another board, and never use OTA to change profiles.

| Board profile | Chip | Flash / PSRAM | Download |
|---|---|---|---|
| `esp32-devkit` | ESP32 | 4 MB / none | `rfbridge-v1.2.0-esp32-devkit.zip` |
| `esp32s3-devkitc-n16r8` | ESP32-S3 | 16 MB / 8 MB Octal | `rfbridge-v1.2.0-esp32s3-devkitc-n16r8.zip` |
| `xiao-esp32s3` | ESP32-S3 | 8 MB / 8 MB Octal | `rfbridge-v1.2.0-xiao-esp32s3.zip` |
| `esp32s3-supermini-fh4r2` | ESP32-S3 | 4 MB / 2 MB Quad | `rfbridge-v1.2.0-esp32s3-supermini-fh4r2.zip` |

Each zip contains the application image, bootloader, partition table, initial OTA data, a `flash_args` file with offsets, checksums, and license notices. The standalone `rfbridge-v1.2.0-<profile>.bin` assets are the same application images, provided for OTA. `SHA256SUMS` covers every asset.

### Update from an earlier release (OTA)

Use **Web UI > System > Firmware update** with `rfbridge-v1.2.0-<profile>.bin`, or from a source checkout:

```bash
tools/push-ota.sh <hostname>.local rfbridge-v1.2.0-<profile>.bin
```

The device must be on Wi-Fi in service mode `web` or `both`, and the image's profile must match the running board. OTA writes the image to flash as it arrives, so a weak Wi-Fi link can drop the upload; the device then keeps running its current firmware and you can retry from a better position.

### First install, or a board running other firmware (wired)

Extract the zip for your board, then from inside that folder:

```bash
# Optional but recommended if the board already holds learned signals or network settings:
esptool --chip <esp32|esp32s3> --port <serial-port> read-flash 0x9000 0x6000 nvs-backup.bin

esptool --chip <esp32|esp32s3> --port <serial-port> write-flash @flash_args
```

`flash_args` preserves NVS at `0x9000` (size `0x6000`). **Do not run `erase-flash`**, and do not merge these files into one image: padding the gap between the partition table and OTA data would wipe NVS.

## Safety

The Web UI, OTA endpoint, and Wi-Fi setup are intentionally unauthenticated: anyone on the LAN can control the radio, install firmware, or move the device to another network. Only run it on a trusted network and never expose port 80 to the Internet. Use the CC1101 at 3.3 V only, always with an antenna, and follow your local RF regulations.
