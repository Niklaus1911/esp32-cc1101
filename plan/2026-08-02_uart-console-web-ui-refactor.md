# UART Console Inventory and Web UI Refactor Plan

## Scope and Sources

No source changes are proposed in this artifact. The application registers 13 commands in `components/rf_console/rf_console.cpp:1957` (`kCommands`). ESP-IDF's `esp_console_new_repl_uart()` also registers `help`; the repository relies on that at `components/rf_console/rf_console.cpp:2120-2127` and documents it at `README.md:95-117`.

All application handlers return `0` on success and `1` on failure. Unless a command has a specialized result below, successful calls render plain `OK <operation>` and failures render `ERROR <operation>: <esp_err_name> (0x<hex>)` through `print_result()` (`rf_console.cpp:803`). Pretty mode renders the same result semantically as `[ OK ] <operation> completed` or `[FAIL] <operation> failed: ...`. Bad arity/value forms emit the exact `usage: ...` strings in the referenced handlers via `print_usage()` (`rf_console.cpp:830`). Console style starts as nonpersistent `pretty`; `plain` is the stable machine-readable form (`rf_console.cpp:88`, `README.md:109-117`).

## Asynchronous UART Output Surface

These records are part of behavior initiated or observed by the console even though they are not synchronous command returns:

- Accepted frames: `RX RC ...` or `RX RAW ...` with the same fields as `last`; `print_frame()` (`rf_console.cpp:277`). `process_receive_item()` performs decode, duplicate suppression, last-frame update, and callback (`rf_ook.cpp:942-1005`).

## Logic That Must Leave `rf_console.cpp`

1. **RF frame ownership and fan-out (mandatory).** `main.cpp:51-54` installs only `rf_console_on_frame()`, and that symbol itself calls `rf_automation_on_frame()` before queueing UART output (`rf_console.cpp:2207-2224`). A Web receiver cannot subscribe independently. Move automation dispatch and bounded observer fan-out to a transport-neutral RF event service; UART and Web become consumers.
2. **Learn lifecycle (mandatory).** Extract `ConsoleEventType`, `ConsoleEvent`, `PendingLearn`, `stored_signal_from_frame()`, `process_learn_request()`, frame classification/capture, timeout, replacement, and overflow cancellation (`rf_console.cpp:47-70,327-482,702-796,1529-1574`) into a typed learn service. Expose request ID/name/deadline/state/result and explicit cancel/replace semantics. Keep printing in console.
3. **Named-signal operations (recommended).** Add typed service methods for list-with-metadata, learn/create, forget, named replay, and decoded/raw send. This removes the list allocation/retry (`:1475`), named load/dispatch (`:1591`), decoded construction/transport bounds (`:1785`), and server-side raw singleton (`:1833-1938`) from transports. For Web, stage raw timings client-side and submit one validated `RawSignal`; do not share UART's global stage across clients.
4. **Typed snapshots, not rendered status (recommended).** Existing status APIs are reusable. Web should call their structs directly. Keep `render_*`, style, `OutputGuard`, password prompting, ANSI/dashboard formatting, and generic result/usage functions in `rf_console`. A small aggregate status DTO is optional to guarantee one coherent Web response.
5. **System-event fan-out (needed for live Web updates).** Wi-Fi, OTA, and automation currently expose one sink each, occupied by console at `rf_console.cpp:2157-2176`; contracts are `network_wifi.hpp:59-72`, `ota_update.hpp:54-60`, and `rf_automation_event.hpp:38-40`. Introduce a bounded app event hub or make each subsystem support bounded multiple subscribers. Sink callbacks must remain zero-wait and perform no I/O; WebSocket/SSE serialization belongs on a Web worker queue.

## Received-Frame Name Annotation Assessment

- Do not call `rf_storage_list()` plus `rf_storage_load()` per frame. Listing walks/sorts NVS under a mutex with a 1 s timeout (`rf_storage.cpp:23,385-444`), each load takes the same lock (`:363-383`), and the current frame callback is deliberately zero-wait (`rf_console.cpp:2207-2224`). That approach adds NVS wear-independent latency, heap churn, queue pressure, and priority inversion risk.
- Build a bounded RAM catalog once after storage initialization, then update it only after successful learn/create/forget commits. Prefer a single owner task with a fixed-capacity or explicitly memory-budgeted table of `{name, RfStoredSignal, derived identity}` and generation number. Queue frames and catalog mutations to that owner; atomically publish annotated events after matching. Never hold the storage lock or perform HTTP/UART I/O during matching.
- Final equality must use `rf_stored_signals_equivalent()` (`rf_automation_engine.cpp:37-52`), which correctly handles decoded/decoded, raw/raw, and raw/decoded aliases. Reuse or promote `rf_find_unique_stored_signal_match()` (`:54`; declaration `rf_automation_engine.hpp:18-22`) rather than inventing Web-specific equality.
- Fingerprints are hints, not identity. Decoded fingerprint equality is a safe same-encoding prefilter because both matching and hashing use protocol/bits/code (`rf_codec.cpp:463-467,632-641`). Raw fingerprints are scale-quantized and start-order dependent while raw equality permits cyclic alignment/tolerance (`rf_codec.cpp:559-604,643-666`), and raw/decoded fingerprints use different domains. Therefore raw count/derived protocol identity may narrow candidates, but all potentially equivalent raw/cross-encoding entries need canonical equality. A hash collision must never assign a name, and a hash mismatch must not exclude a raw alias unless the prefilter is proven necessary for that comparison class.
- Storage permits multiple names for equivalent signals. Annotation should return a sorted bounded list of all matching names plus `match_count`, `ambiguous`, and `catalog_generation`; never silently choose the first. Automation already treats multiple matches as ambiguous (`rf_automation.cpp:277-296`). Define truncation explicitly if the event DTO caps names.
- Preserve capture safety: annotation runs only for accepted post-deduplication frames emitted at `rf_ook.cpp:997-1004`. Learn must still use both event time and `frame.captured_us` through `classify_learn_frame()` (`rf_console_parse.cpp:151-158`) and cancel on queue loss; annotation must not alter those ordering guarantees.

## Concise Refactor Plan

1. Add a transport-neutral `rf_signal_service` component owning learned-signal catalog, learn state, named replay, validated decoded/raw send, and annotated frame events. Route the sole OOK callback through it, then fan out to automation, UART, and later Web via bounded zero-wait queues.
2. Move command-independent validation and DTOs out of `rf_console`; reduce command handlers to argv parsing plus typed API calls and rendering. Keep UART-only style, prompt, hidden password input, raw staging UX, and text formatting in `rf_console`.
3. Add an app event hub (or bounded multi-sink APIs) for RF, automation, Wi-Fi, and OTA. Have the Web task serialize status and events from copied DTOs only, never from subsystem callback context.
4. Add host tests for catalog rebuild/mutation, decoded/raw/cross-encoding aliases, ambiguous names, raw fingerprint false-negative cases, queue overflow, stale generations, learn timeout/replacement, and parity between UART commands and typed APIs. Verify with host tests, the Unity image build, and `tools/verify-production.sh`; hardware timing/RF behavior still requires approved device testing.
